# Tarot technical SEO audit and limited fixes

Baseline: production merge `56257719769a9980d61bde087c20023af5220b77`, 9 October 2026. Branch: `codex/tarot-technical-seo-20261009`. **Preview only; no merge or production release authorized for this batch.**

## Findings in priority order

1. **Confirmed mobile resource cost, fixed locally.** On a fresh 390×844 Chinese tarot page, initial script responses totalled 1,653,331 decoded bytes. An eagerly imported save panel pulled in the 1,110,265-byte OpenCC character dictionary before any card was placed. Loading the existing panel on demand reduces initial scripts to 530,758 decoded bytes (67.9% reduction). The same save component and account operations run after placement; no account, AI, payment or persistence code changed. This is a resource measurement, not a Core Web Vitals field result, network-byte claim or ranking prediction.
2. **Incorrect document language, bounded mitigation.** All 36 sampled initial documents use root `html lang="en"`, including non-English pages; every localized `main` correctly declares its language and contains the full server-rendered text. A tiny tarot-only client component now synchronizes the browser document to the server-selected language and restores its previous value when unmounted. Four-language navigation/history passes. **Raw HTML still has the existing `lang="en"`; this is not presented as a server-root fix.** Making the shared root depend on request headers would widen dynamic rendering to other businesses, while a root-layout/locale-route restructuring exceeds this scope. Google explicitly says language detection uses page content rather than HTML lang, so this is not established as an indexing blocker.
3. **Missing tarot Open Graph locale, fixed.** `/tarot` provided no `og:locale` in any of the four language editions; its child metadata replaces the root Open Graph object. It now emits the selected locale plus the other three locales. Article metadata was already correct and is unchanged. This is sharing metadata consistency, not a traffic guarantee.
4. **No missing tarot sitemap cluster found.** The actual sitemap contains 942 unique URLs. All 316 atlas/card URLs—79 pages × four languages—are present. Full 312-card-edition regression verifies canonical, reciprocal language alternates, complete text, sources and sitemap. All 16 educational editions and 77 internal-link destinations also pass. Existing atlas/table/guide links were not duplicated. Robots allows tarot and Journal.
5. **No justified image or title rewrite.** Mobile requests the existing 126,524-byte portrait landscape, not the 290 KB desktop image; the table's foreground artwork adds 66,694 bytes. Existing card images use the established lazy/responsive pipeline. Page titles, descriptions, URLs, canonical/hreflang generators, manuscripts and the visual design are untouched. The shared global CSS remains a possible later performance investigation, not a reason to broaden this patch.

## Evidence and verification

- `baseline.json` and `after-report.json`: nine routes × four languages, Googlebot raw response parsed with JavaScript disabled; SSR body, headings, title/description, canonical, alternates, robots, structured data and links are recorded. Browser resource inventories use a fresh page at 390×844, initial load plus two seconds. Results are from the local production build.
- `resource-comparison.json`: exact decoded script totals. Atlas and Sun article scripts increase by 1,571 bytes for the document-language helper; they do not acquire the OpenCC dictionary.
- `after-report.json`: sitemap uniqueness and all 316 tarot URLs; four real placement → deferred save-panel → atlas/language → Back/Forward workflows. Writes to account/AI endpoints are blocked during browser verification; no real account records are created.
- Build and explicit TypeScript check pass. Scoped lint has zero errors and the existing card-image warning. All 21 celestial unit tests pass.
- `interaction-report.json`: 16 four-language keyboard/touch, shuffle, placement, unique cards, reshuffle/reset, meaning/article and return workflows pass. `fan-report.json` passes 12 fully settled wide-screen states in normal/reduced motion with pixel readback of both exposed wings. `scene-report.json` passes 28 four-language viewport cases, including 360/390/430 mobile and 1165×757 / 1280×720 short desktops; fan geometry and first-screen actions remain intact.
- The source changes are limited to the tarot page metadata, a dynamic import in the tarot client, its header, and a small language synchronizer. React review checked stable effect dependencies, cleanup, no hydration suppression, no heavy helper imports into the synchronizer, and a statically analyzable lazy-import path.
